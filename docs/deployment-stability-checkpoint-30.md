## Corrections

Use the installed `WC_Subscriptions_Product::get_period/get_interval` API rather than nonexistent billing getters on the product. Validate supported terms and customer identity. Create a pending subscription, a zero-subtotal/zero-total/zero-tax line for the configured product, manual renewal, no payment method and no next-payment date. Calculate totals without regenerating taxes; reject nonzero total. Use `wcs_add_time(interval, period, start)` for exactly one billing period, save terms, then activate through the installed subscription API.

Both automatic award and explicit candidate approval call the same once-per-month service. A unique, non-autoloaded options row is inserted before creating the subscription; the new pending subscription identity is conditionally saved before activation. Claim updates compare the exact expected payload. Completed or uncertain claims never trigger another automatic attempt. Exceptions retain `needs_review` where that update can be persisted; failed final completion leaves an existing started claim, which also blocks retry. If the database remains unavailable after creation, the identity might not be durable, but the original claim still prevents blind recreation: staff must investigate rather than delete the claim.

The unsafe reset-awarded-month checkbox is removed, and old submitted reset fields no longer clear history. Settings show the selected/current month's claim state and subscription ID. Candidate email instructions now direct approval of the queued candidate without enabling automatic fulfillment. No real candidate/email was generated by verification. Existing last-winner options are compatibility projections; the new claim is the duplicate-prevention authority. Historic months without claims are not inferred or migrated.
